문서웹 · 링크
  • 이 계획서: claude.ai 공유 링크. 페이지의 Share(공유) 메뉴에서 참석자에게 먼저 공유해야 열립니다. 아래 QR로 각자 휴대폰에서 같이 봅니다.

07

AI로 개발하기 · 입문자용

이 프로젝트는 지금까지 AI와 함께 이 흐름으로 만들어 왔습니다. 작업 하나마다 같은 여섯 단계를 반복합니다. 회의 중 시연에서는 프롬프트를 개발 PC 메모장에서 복사하고, 회의 뒤 각자 자리에서는 아래 복사 버튼을 씁니다.

  1. 읽히기시작할 때마다 규칙·로드맵·기술구조 문서를 AI에게 먼저 읽힙니다. 대화가 길어지면 앞 내용을 잊으므로, 작업마다 새 대화로 시작합니다.
  2. 계획 받기코드를 고치기 전에 바꿀 파일과 순서를 계획으로 받습니다. 구버전 파일이 있거나 너무 많은 파일을 건드리면 여기서 고칩니다.
  3. 작게 진행한 번에 한 단계만. 끝나면 무엇을 바꿨는지 짧게 듣고 다음 단계로.
  4. 검사python tools/tests/run_all.py (일부만: run_all.py zone2처럼 이름). 결과를 직접 읽고, 게임 화면에서 눈으로 확인합니다.
  5. 이해 확인"바뀐 부분을 설명해줘", git diff를 직접 봅니다. 이해가 안 되는 변경은 받아들이지 않습니다.
  6. 기록 · PR작업기록 맨 위에 항목, 정한 것이 있으면 결정기록, 한글 커밋, PR.

지킬 것

  • 계획을 먼저 받고, 바뀔 파일 목록을 확인한다.
  • "완료"라는 말 대신 검사 결과와 게임 화면을 본다.

조심할 것

  • AI가 구버전 파일을 고치려 하면 멈춘다.
  • 모르는 git 명령(reset, push --force, 삭제)은 허락하지 않고 A에게 묻는다.

  • 밸런스 숫자는 담당자 말고는 바꾸지 않는다 (의견만 전달).
