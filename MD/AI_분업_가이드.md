# AI 분업 가이드 (Claude · Codex · Gemini) — D-052

Claude가 지휘하고 검증한다. Codex는 간단한 코딩, Gemini는 그림을 맡는다.
**결과는 Claude가 확인한 것만 게임에 넣고 커밋한다.**

| 누구 | 맡는 일 | 연결 방법 |
|---|---|---|
| **Claude** (Claude Code) | 할 일 나누기, 브리프·프롬프트 쓰기, 결과 검증, 문서 기록, 커밋 | — |
| **Codex** | 간단한 코딩: 범위가 분명한 함수 추가, 수치·문구 바꾸기, 같은 모양 반복 수정, 원인이 밝혀진 작은 버그 | Codex 앱에 들어 있는 CLI → `tools/ai/codex_task.py` |
| **Gemini** | 그림 (거점·적·배경·캐릭터) | 크롬(Claude in Chrome 확장)에서 Claude가 gemini.google.com을 직접 조작 |

---

## 1. Codex에게 코딩 맡기기

**맡기는 일**: 고칠 파일과 할 일을 한두 문단으로 정확히 적을 수 있는 일.
**맡기지 않는 일**: 설계가 필요한 일, 여러 모듈에 걸친 구조 변경, 기획·밸런스 판단, 구버전 코드(`js/engine/`, `js/ui/`, `js/main.js`).

### 절차
1. **Claude가 브리프를 쓴다** (아래 틀). 공통 규칙은 스크립트가 앞에 붙인다: `.agents/AGENTS.md` 따르기, 적힌 파일만 고치기, 커밋·브랜치·`MD/` 수정 금지, 끝나면 한국어 보고.
2. **실행** (Claude가 백그라운드로):
   ```
   python tools/ai/codex_task.py <브리프.md> --name <이름>
   ```
   | 옵션 | 뜻 |
   |---|---|
   | `--read-only` | 조사·답만 (파일 수정 금지) |
   | `--timeout 분` | 시간 제한, 기본 20분 — 넘기면 끝내고 실패로 남김 |
   | `--effort low\|medium\|high` | 생각 깊이 (기본은 `~/.codex/config.toml`) |
   | `--image 그림...` | 화면 캡처 등 그림을 같이 보냄 |
   기록: `tools/ai/_runs/<시각>_<이름>/` — `prompt.md`(보낸 글), `log.txt`, `result.md`(Codex 보고), `changes.txt`(Codex가 바꾼 파일), `diff.patch`. 저장소에는 올리지 않음.
3. **Claude가 검증한다**
   - [ ] 바뀐 파일이 브리프에 적은 파일뿐인가 (`changes.txt`)
   - [ ] diff를 한 줄씩 읽는다: 요청대로인가, 주변 코드 모양을 따랐나, 범위 밖 수정·구버전 파일 수정은 없나
   - [ ] `node --check`, 관련 자동 검사(`python tools/tests/run_all.py` 또는 해당 `test_*.py`)
   - [ ] 화면이 바뀌는 일이면 게임을 띄워 직접 확인
4. **통과** → Claude가 작업기록에 `(Codex 작성 · Claude 검증)`으로 남기고 커밋.
   **실패** → 고칠 점을 적어 다시 맡기거나(같은 일은 최대 2번), Claude가 직접 고친다.

- Codex가 도는 동안 Claude는 같은 파일을 고치지 않는다. Codex는 커밋하지 않는다.
- `changes.txt`는 실행 전후 비교라서, Codex가 도는 동안 Claude가 **다른 파일**을 고쳐도 그 파일이 섞여 나온다 → diff를 볼 때 내가 고친 파일은 빼고 본다.
- 로그인은 Codex 앱과 같다(`~/.codex`). 앱이 업데이트되어 CLI 폴더가 바뀌어도 스크립트가 최신 것을 찾는다.

### 브리프 틀
```
목표: (한 문장)
고칠 파일: (경로 목록)
할 일:
1. (함수·변수 이름, 값, 위치까지 구체적으로)
2. ...
하지 말 것: (있으면)
다 됐다는 기준: (예: node --check 통과, X를 부르면 Y)
참고할 곳: (읽어 볼 파일·함수)
```

## 2. Gemini에게 그림 맡기기 (크롬 조종)

Pro 구독 안에서 받으므로 추가 비용 없음. 대신 화면을 직접 조작해서 느리고, Gemini 화면이 바뀌면 깨질 수 있다.

### 준비 (처음 한 번 — 사용자)
1. 크롬에 **Claude in Chrome** 확장 설치: https://chromewebstore.google.com/detail/fcoeoabgfenejglbffodgkkbkcdhcgfn
2. 크롬 오른쪽 위 확장 아이콘 → Claude 옆 패널을 열고 **Claude 데스크톱 앱과 같은 계정**으로 로그인
3. 같은 크롬에서 gemini.google.com에 Pro 구독 Google 계정으로 로그인되어 있을 것
4. Claude가 처음 gemini.google.com에 들어갈 때 사이트 허용을 물으면 허용

### 절차 (Claude)
1. `이미지_제작_가이드.md`의 공통 스타일 + 단계 프롬프트로 **완성 프롬프트**를 만든다 (영문, D-031).
2. 크롬에 **새 탭** → gemini.google.com → 대상이 바뀌면 새 대화, 변형 단계(STEP 2·3)면 같은 대화.
   - 그림 모드: 입력칸 왼쪽 **업로드 및 도구(+) → 이미지 만들기** (입력칸에 `이미지` 칩이 생김). 비율은 입력칸 아래 **기본 비율** 목록에서.
   - 참고 그림 첨부: 파일 입력칸이 미리 없어서 [tools/ai/gemini_upload_hook.js](../tools/ai/gemini_upload_hook.js)를 먼저 실행 → **업로드 및 도구 → 파일 업로드** → `claude-upload-input`에 `file_upload` → `__claudeHookRestore()`.
   - 프롬프트 입력 → 보내기. 그림 한 장 약 20초.
3. 나온 그림을 화면으로 먼저 보고 **쓸 만한 것만** 고른다. 안 되면 고칠 문장(`In this image, change only ...`)으로 다시.
4. **내려받기 전에 사용자에게 확인** (파일 이름·개수) → 그림 위 **원본 크기 이미지 다운로드** → `Downloads\Gemini_Generated_Image_*.png`를 정해진 폴더·이름으로 옮김 → `tools/images/unlogo.py`(로고 지우기) → `tools/images/check_image.py`(자동 검사·게임 크기 미리보기, Bash에서는 `PYTHONIOENCODING=utf-8`을 앞에 붙임).
5. 사용자에게 결과와 미리보기를 보여 준다.

### 시험 결과 (2026-10-16)
- 로그인(Pro) 확인, 시험 프롬프트(빨간 상자, 초록 배경) → 약 20초 만에 그림 나옴. 참고 그림 첨부도 위 방법으로 됨.
- 화면에 보이는 그림은 미리보기 **1024×572**, 원본 크기 다운로드는 **2752×1536 PNG (약 4.5MB)** — 기본 비율 16:9.
- 원본 크기는 Gemini 로고가 **96px, 여백 64px로 고정**이라 예전 크기 비례 예측으로는 안 지워짐 → `unlogo.py`에 2752×1536을 따로 등록 (Codex 작업, 아래 작업기록).
- 크롬이 내려받을 때마다 **다른 이름으로 저장** 창을 띄움 (크롬 설정 "다운로드 전에 각 파일의 저장 위치 확인"이 켜져 있음). 이 창은 Claude가 누를 수 없음 → 사용자가 저장을 누르거나, 설정 → 다운로드에서 그 항목을 끄면 바로 저장됨.
- 고를 수 있는 모델: 3.5 Flash-Lite / 3.8 Flash / 3.1 Pro / 4 Argon (+ 사고 수준).

### 실제 작업 요령 (2026-10-16, 거대괴수 A 세트)
- **크롬 창을 Claude 전용으로 하나 더** 열어 둔다 → Claude는 그 창의 Claude 탭 그룹에서만 움직이고, 사용자가 쓰는 창과 겹치지 않는다.
- 원본이 여러 그림이 든 시트면 **쓰는 부분만 잘라 3배로 키워** 첨부 → Gemini가 첨부 그림의 비율·자리를 그대로 지킴 (전신이 원본과 배율·이동 없이 겹침).
- 같은 대화에서 이어 고치면 캔버스 비율이 조금 바뀔 수 있음 (2338×1792 → 2400×1792) → 높이를 맞추고 몇 px 이동으로 맞춘다.
- 결과를 내려받기 전에 페이지 안에서 원본과 윤곽 겹침(IoU)을 재서 자리를 먼저 확인할 수 있다 (첨부 그림과 결과 그림이 둘 다 페이지에 있음).
- "팔·아래턱·꼬리 지우기"에서 **아래턱이 남는 일이 있음** (B 세트) → 확대해서 보고, 같은 대화에서 "아래턱이 아직 있다, 아래 이빨까지 모두 지우고 윗턱 아래는 입안만"으로 다시 요청하면 지워짐. 내려받을 때는 고친 마지막 그림만.
- 모양을 크게 바꾸는 요청(예: "길고 가는 다리")과 "자리 그대로"가 부딪히면 Gemini는 자리를 지키는 쪽 → 모양이 꼭 필요하면 자르는 선을 새로 정해야 함.

### 앱 내장 브라우저로는? (2026-10-16 확인)
Claude 데스크톱 앱 안의 브라우저 창에서도 gemini.google.com을 열고 조작할 수 있다 (확장 필요 없음, 앱 안에서 바로 보임).
다만 지금은 **크롬을 기본으로** 쓴다:
- 내장 브라우저는 **다른 Google 계정**(gogo251023@…)으로 로그인돼 있음 — Pro 계정으로 쓰려면 사용자가 그 창에서 다시 로그인.
- 내장 브라우저 도구에는 **파일 첨부 도구가 없음**. 우회 방법을 시험한 결과 (첨부만 시험, 보내지 않음):
  | 방법 | 결과 |
  |---|---|
  | 클립보드에 그림 복사 → 입력칸에서 Ctrl+V | ✗ Claude가 보내는 키 입력은 진짜 붙여넣기로 처리되지 않음 |
  | 페이지가 클립보드를 직접 읽기 (`navigator.clipboard.read`) | ✗ 읽기 권한 거부 |
  | 내 컴퓨터의 작은 서버에서 그림 가져오기 (fetch / img) | ✗ Gemini 보안 정책(`connect-src`·`img-src`)이 Google 주소만 허용 |
  | 파일 입력칸에 경로 넣기 (`form_input`) | ✗ 브라우저 보안상 경로를 넣을 수 없음 |
  | **페이지 안에서 그림 파일을 만들어 입력칸에 넣기** (가로채기 + `DataTransfer`) | ✓ **첨부됨** (페이지에서 그린 시험 그림, 10-16) — 남은 문제는 그림 데이터를 페이지로 옮기는 것뿐 |
- 그림 데이터를 옮기는 길은 Claude가 그림을 글자(base64)로 바꿔 스크립트에 직접 넣는 것뿐 (Gemini 보안 정책이 다른 경로를 막음). 참고 그림 한 장(괴수 원본 잘라 16색 = 약 5만 자)마다 1~2분, 글자가 많아 무겁고 옮기다 틀릴 수 있어 확인(해시)이 필요. 새 대화마다 원본 한 장만 옮기면 되고, 같은 대화의 후속 단계는 필요 없음.
- 원본 크기 내려받기가 되는지·어디로 저장되는지 아직 확인 안 함 (안 되면 결과 그림을 꺼낼 길이 없음).
→ 지금은 **크롬이 빠르고 확실**. 크롬을 쓰시는 동안 방해되면 크롬 창을 하나 더 열어 Claude 탭 그룹은 그 창에서만 움직이게 한다.

### 제한
- 그림 한 장당 **다시 뽑기 최대 3번**. 그래도 안 되면 프롬프트를 사용자와 다시 정한다.
- 페이지가 응답하지 않거나 같은 조작이 2~3번 실패하면 멈추고 보고한다 (기다리기만 하지 않음).
- 크롬 조종이 막히면 예전 방식(사용자가 직접 받아 채팅에 첨부, `이미지_제작_가이드.md` 0절)으로.
